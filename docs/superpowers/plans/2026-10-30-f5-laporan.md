# F5 — Laporan & BI: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard utama dan laporan back-office sesuai requirement manager: penjualan periode, detail transaksi, jenis pembayaran, void & refund, produk & kategori terlaris (dengan HPP & laba kotor), promo & kupon, pajak, penjualan per kasir, serta jam & hari ramai (umum dan per produk) — dengan export CSV.

**Architecture:** Satu loader `loadReportData(outletId, period)` membaca bill, item, refund dan promo untuk rentang hari bisnis lewat `readDb`, menghasilkan baris ringan. Semua angka dihitung oleh fungsi murni di `src/lib/reports/` (teruji tanpa DB) dan dipakai halaman maupun export CSV, sehingga layar dan file selalu sama. Halaman admin adalah server component dengan pemilih periode di query string.

**Tech Stack:** Next.js 15, Prisma (readDb), recharts (seperti tokatalog), vitest.

**Spec:** `docs/PLAN.md` — "Fase F5" + "Keputusan F5"; requirement manager "Modul Pelaporan & Analitik" A–E. Laporan Kas Kasir & Tutup Kasir sudah ada di F3 (`/admin/shifts`) dan hanya ditautkan.

## Global Constraints

- Hari bisnis (`business_date` bill; refund pakai `businessDateWIB(refund.created_at)`), WIB, uang integer rupiah.
- Definisi angka persis seperti tabel "Keputusan F5" (transaksi, penjualan kotor, pendapatan bersih, pajak, penjualan tanpa pajak, laba kotor, rata-rata per transaksi).
- Bill `open`/`void` tidak masuk penjualan; void dihitung di laporan void.
- CSV: pemisah `;`, UTF-8 BOM, CRLF, sel dikutip bila berisi `;`/`"`/baris baru, angka tanpa pemisah ribuan.
- Grafik mengikuti skill `dataviz` (muat sebelum menulis kode grafik pertama); gaya visual F1–F4.

## Review Focus

1. **Bill dibayar lewat tengah malam** (01:30 WIB): masuk hari bisnis sebelumnya di laporan harian, sedangkan heatmap jam ramai memakai jam dinding (Sabtu 01:00). → test Task 1.
2. **Refund di hari berbeda dari penjualannya**: penjualan tetap di hari asal; refund mengurangi pendapatan bersih hari refund; laporan periode yang hanya mencakup salah satu hari tetap konsisten. → test Task 1.
3. **Periode tanpa transaksi / periode pembanding nol**: tidak ada pembagian dengan nol; persentase tampil "—", bukan `NaN`/`Infinity`. → test Task 1.
4. **Nama produk/promo yang sudah diubah atau dihapus**: laporan memakai snapshot nama di bill (`OrderItem.name`, `Order.promo_name`), dikelompokkan per `product_id` dengan nama terbaru di bill. → test Task 1.
5. **Teks berisi `;`, kutip, atau baris baru di CSV** (catatan, nama customer): file tetap terbaca per kolom. → test Task 2.

### Task 1: Periode & agregasi (modul murni)

**Files:** Create `src/lib/reports/period.ts`, `src/lib/reports/aggregate.ts`, `src/lib/reports/types.ts`; tests `period.test.ts`, `aggregate.test.ts`

**Interfaces (Produces):**
- `type Period = { from: string; to: string }` (hari bisnis inklusif); `PRESETS = ['today','yesterday','7d','30d','this_month','last_month'] as const`; `resolvePeriod(preset | {from,to}, today: string): Period`; `previousPeriod(p: Period): Period` (sama panjang, tepat sebelum); `daysIn(p): string[]`.
- `type ReportOrder = { id; code; number; business_date; status; order_type; customer_name; created_by; paid_by; paid_at: string|null; total; subtotal; discount; tax; promo_id; promo_name; payment_method; void_reason; voided_by; items: { product_id; category_id; category_name; name; qty; paid; cogs; refunded_qty; refunded_amount; options: string[] }[] }`; `type ReportRefund = { id; order_id; order_code; business_date; method; amount; tax; reason; employee_id; created_at; items: { name; qty; amount }[] }`; `type ReportData = { period: Period; orders: ReportOrder[]; refunds: ReportRefund[]; employees: Record<string,string> }`.
- `summary(d: ReportData): Summary` = { transactions, gross_sales, refunds, net_revenue, tax, net_of_tax, cogs, gross_profit, avg_ticket, discounts, promo_orders, voids }.
- `byDay(d): { date; transactions; net_revenue; gross_profit }[]` (semua hari di periode, nol bila kosong).
- `byPayment(d): { methods: { method; transactions; amount; share }[]; refunds: { cash; cashless } }` — `amount` = Σ total bill per metode (kotor), `share` 0–1 dari penjualan kotor; refund ditampilkan terpisah (tunai dari laci / non-tunai).
- `byProduct(d)`, `byCategory(d)`: { key; name; qty; revenue (Σ paid − refunded_amount); cogs; gross_profit (revenue tanpa pajak − cogs) } urut revenue turun.
- `byCashier(d)`: per `paid_by` { name; transactions; gross_sales; avg_ticket }.
- `byPromo(d)`: per promo { name; uses; discount; sales; avg_ticket } + baris "Tanpa promo" untuk pembanding.
- `taxReport(d)`: per hari { date; tax_sales; tax_refunds; tax_net }.
- `voidsAndRefunds(d)`: { voids: [...order, reason, by]; refunds: [...] ; totals }.
- `heatmap(d, filter?: { product_id })`: matriks 7×24 (hari Senin..Minggu × jam WIB) { transactions, revenue } berdasarkan `paid_at` (per produk: qty item).
- `change(current: number, previous: number): number | null` (null bila previous = 0).

- [ ] **Step 1: Failing tests** dengan fixture kecil (3 hari, 2 kasir, tunai/QRIS/EDC, 1 void, 1 refund di hari berikutnya, 1 bill dibayar 01:30 WIB, 1 promo yang namanya berubah):
  - `summary` sesuai definisi (angka dihitung tangan di test).
  - Review Focus 1: bill 01:30 WIB 31 Okt → hari bisnis 30 Okt di `byDay`; heatmap memakai jam dinding WIB saat bayar → sel **Sabtu** jam 1.
  - Review Focus 2: periode hanya 30 Okt → penjualan ada, refund 31 Okt tidak; periode 31 Okt → refund mengurangi pendapatan bersih, transaksi 0.
  - Review Focus 3: data kosong → semua nol, `avg_ticket 0`; `change(10, 0)` null; `change(0, 0)` null; `change(15, 10)` 0.5.
  - Review Focus 4: dua bill produk sama dengan nama berbeda → satu baris di `byProduct` memakai nama dari bill terbaru.
  - `resolvePeriod('this_month', '2026-10-30')` → `2026-10-01..2026-10-30`; `previousPeriod({2026-10-24..2026-10-30})` → `2026-10-17..2026-10-23`; `resolvePeriod('last_month', '2026-03-15')` → `2026-02-01..2026-02-28`.

### Task 2: Loader & CSV

**Interfaces:**
- `loadReportData(outletId: string, period: Period): Promise<ReportData>` — bill dengan `business_date` di periode dan status `paid|refunded|void` (+ item, opsi, kategori), refund dengan `created_at` di rentang UTC periode (lalu `business_date` dihitung), nama karyawan; lewat `readDb`.
